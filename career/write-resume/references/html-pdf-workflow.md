# HTML/PDF 固定流水线

只在生成或排查正式 HTML/PDF 简历时读取本文件。内容写作仍按 `resume-patterns.md` 执行。

## 为什么固定流程

HTML 简历导出 PDF 的高风险点不是写 CSS，而是多个工具各自“看似成功”：

- 在受限沙箱中，Chrome 可能以退出码 0 结束却不创建 PDF。
- Chrome 也可能已经写完 PDF 但父进程迟迟不退出，造成无意义的长时间等待。
- `--print-to-pdf-no-header` 在部分新版 Chrome 中不会单独关闭自动页眉页脚。
- macOS 的苹方字体视觉正常，但某些 PDF 文本映射会把“支付、风控”等汉字编码成 CJK 部首字符，降低 ATS 关键词命中率。
- 用 `position: relative` 和伪元素画章节强调线，可能让 PDF 文本层把章节标题集中排到正文末尾，视觉却完全正常。
- 对整个长项目使用 `break-inside: avoid` 会把项目整体推到下一页，产生大面积空白。
- bullet、项目描述、角色说明或标题可能在打印排版后只在末行留下 1-5 个字；HTML 屏幕预览可能看不出，PDF 技术上也完全正常，但快速浏览体验明显不合格。
- 重复使用同一个 PNG 目录会残留旧页面，让页数和视觉检查产生假阳性。
- 直接改标准模板会污染后续任务；复制后忘记删除模板人物、公司或指标，则会把示例事实混进候选人简历。
- 直接覆盖最终 PDF 时，如果新一轮构建失败，上一版也可能丢失。

`scripts/resume_pipeline.py` 把这些风险变成显式失败。

## 固定顺序

1. `doctor` 检查 Chrome、Poppler、FontTools、pypdf、pdfplumber、PingFang SC 与 ATS 后备字体。
2. `init` 从标准模板创建新 HTML，并写入模板 SHA-256 指纹。
3. 只修改新 HTML；标准模板保持只读。
4. `build` 先按 HTML 正文实际字符从本机 PingFang SC 生成 Regular、Medium、Semibold 子集，再输出候选 PDF 到本次独立 QA 目录。
5. 自动检查通过后，脚本才原子替换最终 PDF。
6. 脚本为每次构建创建新的 `run-时间-进程号/`，输出逐页 PNG、可用时生成 contact sheet，并写入 `qa-report.json`。
7. 人工查看最新 PNG；自动检查不能判断视觉密度、内容层级是否舒服或某个分页是否在语义上合理。

## 脚本保证

### 模板来源

- `build` 拒绝直接处理标准模板。
- 没有 `init` 指纹的 HTML 会被拒绝。
- 指纹落后于当前模板时默认停止，防止继续使用未修复的旧模板。
- 标准示例中的姓名、日期占位、虚构公司和代表性指标短语默认列为禁用残留。

### PDF 生成

- Chrome 使用独立临时 profile，避免复用有状态浏览器会话。
- 同时传入 `--no-pdf-header-footer` 和 `--print-to-pdf-no-header`，兼容新旧 Chrome。
- 即使 Chrome 返回 0，脚本仍要求 PDF 实际存在且大小合理。
- PDF 文件达到合理大小并稳定后，脚本主动结束本轮 Chrome 进程组，不等待浏览器后台组件自然退出。
- 构建在临时 PDF 上完成；所有自动检查通过后才替换最终文件。

### ATS、字体与逻辑结构

- 标准模板使用 `ResumePingFang`、SF Pro 和 Arial Unicode 后备字体栈：英文与数字由 SF Pro 渲染，中文由当前简历专属的 PingFang SC 子集渲染；Arial Unicode 只处理缺字。
- PingFang SC 系统字体包含部分共享字形映射，Chrome 直接调用时可能把常用汉字写成 CJK 部首。流水线只保留 HTML 正文实际出现的 Unicode 映射，生成的渲染副本和字体子集位于本轮 QA 目录，不进入最终交付目录，也不会与并行构建互相覆盖。
- 脚本直接扫描 PDF 提取文本中的 CJK 部首区段，发现泄漏立即失败。
- PDF 必须是纵向 A4、可提取文本、每页非空；每个 HTML 章节标题不仅要保持顺序，还必须出现在该章节首段正文之前。
- PDF 的第一段文本必须来自 HTML body，且不得出现 `file:///`，用于发现浏览器自动页眉页脚和阅读顺序异常。
- `--required-term` 用于验证目标 JD 的核心词确实能被解析；只在 HTML 里肉眼可见不算通过。
- 每个非末页默认至少使用 72% 的页面高度，拦截因粗暴分页规则造成的明显空洞；末页不做同样限制。
- 脚本把 HTML 中的 `<li>`、`<p>`、项目标题以及关键头部信息映射到 PDF 实际视觉行。任何跨行文本块的末行必须同时包含至少 8 个有效字符，并达到该文本块前序参考行宽的 15%；无法可靠映射或任一阈值不满足都会失败，且没有关闭参数。字数上限不能替代此检查，因为中英文、数字、字重和字体的实际宽度不同。

## 常见失败

### Chrome 返回但没有 PDF

含义通常是 GUI/沙箱权限阻止了 Chrome。对原 build 命令申请权限后原样重跑。不要手动改成另一条 Chrome 命令，否则会丢失固定参数和自动检查。

### Missing template fingerprint

HTML 不是由当前 skill 的 `init` 创建。重新初始化，再把内容修改迁移到新副本；不要手工伪造指纹。

### Copied HTML was created from an older template

标准模板在副本创建后有过修复。优先重新 `init` 并迁移内容。只有人工比较过差异且确认旧模板安全时才使用 `--allow-stale-template`。

### Template/sample text still present

副本仍含模板人物、公司、日期占位或示例指标。替换成用户可核验事实；Mock 简历也应使用新构造且明确标注为虚构的数据。

### CJK radical code points

PDF 的中文文本编码不适合 ATS。确认使用当前标准模板和固定流水线，并删除对 `ResumePingFang` 声明的任何修改；重新运行 `doctor`，让 `build` 按最终 HTML 正文重新生成字体子集后再构建。若当前环境仍无法安全导出 PingFang SC，停止交付并说明限制；不得静默把 Arial Unicode 提升为默认视觉字体。视觉正常不能豁免该错误。

### 页数不符

先查看本轮 PNG 判断是内容溢出、项目被整体移页还是字体/间距变化。修改 HTML 副本后使用 `--overwrite` 重建；不要为了强制一页删除高价值证据或破坏模板视觉语言。

### Section heading after its content

章节标题在视觉上正确，但 PDF 文本层把标题放到了正文之后。不要用定位元素或伪元素承载章节条；标准模板使用浅蓝背景加原生 `border-left`，既保留视觉强调，也保持 ATS 阅读顺序。

### Non-final pages have excessive bottom whitespace

非末页填充率低于默认 72%。先取消对整个长项目的 `break-inside: avoid`，只保护项目内的小节；再检查是否存在不必要的显式分页。只有视觉复核确认留白有意且合理时，才把 `--min-nonfinal-fill` 调低或设为 0。

### Wrapped text-block orphan lines detected

某个 bullet、段落、项目标题或关键头部信息换行后，末行有效字符少于 8 个，或相对该文本块参考行宽低于 15%。错误信息会列出页码、文本块类型、末行文本和原文。优先删减低价值修饰、合并同义表达或调整语序，使内容自然回流到上一行；如果必须保留全部证据，则把末行扩展成有完整信息价值的一行。不得通过缩小全局字号、压缩打印边距、固定粗略字数或修改脚本阈值绕过。

## 人工视觉检查

逐页确认：

- 蓝色主色、浅蓝整行章节条和左侧蓝色强调线仍在。
- 姓名、联系方式、目标岗位层级清楚；公司与日期对齐。
- 项目标题、标签与 bullet 没有孤行、截断、覆盖或异常拆页。
- 所有跨行 bullet、段落、项目标题和关键头部信息的末行都具有完整语义和足够视觉宽度；自动阈值通过后仍需肉眼复核整页节奏。
- 没有浏览器日期、标题、文件路径或页码。
- 字号可读，页面密度均衡；第二页不因强制分页出现明显空洞。
- PDF 字体资源中，中文显示为 `PingFangSC`，英文与数字显示为 `.SFNS` 或 `SF Pro`，没有被 Arial Unicode 等后备字体整体替代。
- Mock 文件有醒目标识，真实投递文件没有虚构数据或模板残留。
