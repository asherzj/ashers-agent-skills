# 小改动交付流程

依次组合 `grill-with-docs` 和 `implement`，不要复制它们的内部操作。开始前读取仓库的 `AGENTS.md` 或 `CLAUDE.md`，让领域术语、ADR 和工单规则贯穿全程。

## 入口判断

只有同时满足以下条件才使用本流程：

- 只改变一个连贯、可观察的行为；
- 能在一次实现上下文和一次工单级提交中完成；
- 不需要独立决策地图、正式规格或多工单依赖图。

澄清后如果出现多个可独立交付的切片，转用 `flow-feature`；如果路线仍然迷雾重重，转用 `flow-large-effort`。

## 流程

1. 输入是未经整理的口述或逐字稿时先调用 `from-transcript`；否则直接调用 `grill-with-docs`。明确预期行为、范围、领域语言、验收接缝，以及至少一个正常或关键异常验收例子，并保留当前对话作为实现的一手来源。
2. 把共识整理成一份简短实现说明。除非用户或仓库流程要求，否则不要为了小改动额外创建 Issue。
3. 在同一上下文调用 `implement`。由它负责验收外循环、适用时的红绿 TDD 切片、分层验证、双轴代码评审、上下文更新、提交、推送和工单收尾。

不要顺手扩大范围做相邻清理；新发现的工作应单独提出。

## 完成条件

汇报交付行为、验收证据、分层验证、评审结论、上下文更新、提交与远端分支，以及存在 Issue 时的最终状态。达到仓库定义的完整功能门槛时，先执行项目级完成钩子。任何必要检查、权限或推送受阻时，停在边界并明确说明，不能声称已经交付。
